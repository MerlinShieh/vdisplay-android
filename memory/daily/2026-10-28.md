## 截图不能落 /sdcard（已修复的污染问题）

用户的批评：读屏截图存到 `/sdcard/DCIM/Minis/` 会
1. 占存储（实测残留 8.5MB）
2. 被系统相册识别成用户保存的图片
3. 更糟：`rm` 后不是真删，MediaStore 会改名成 `.trashed-<id>-<name>` 塞进回收站，文件仍在、记录仍在

**根治方案（已落地）**：截图完全不经过 `/sdcard`
- 设备端截到 `/data/local/tmp/.vs/`（MediaStore 不扫描该路径，实测 `content query` 记录数 0）
- `assets/pull.sh` 用 nc 裸流拉回沙箱，**设备端必须用 `nc -q 1`**；用 `-w 20` 会让每张图卡 30 秒（实测 31s → 2s）
- `assets/grab.sh <本地> [包名] [--raw]` 一条龙：截 → 拉 → 删设备端，约 3 秒/张，默认压成 360×640 JPEG
- 批量：设备端循环 shot 到 `.vs/`，tar 打包一次 pull（单次别超 ~3MB，会截断）
- **禁用** `android-photos list/export` 和 `MEDIA_SCANNER_SCAN_FILE` 处理截图

已同步：SKILL.md 截图章节整段重写、GLOBAL.md 抓屏条目、清空 `/sdcard/DCIM/Minis`（含 trashed 残留，媒体库记录已归零）。

## input 注入的静默失败陷阱

- `input` 语法：`input [<source>] [-d DISPLAY_ID] <command> [args]`，**`-d` 必须在子命令前**。
- `vdisplay swipe` 曾因参数错位（把 `$6` 当时长、`$7` 当包名，实际 `$6` 是时长、`$7` 是包名，但代码反了）导致**整条命令静默失败**：画面 md5 完全不变，因为事件注入了默认屏。
- 排查方法：操作前后对比 `screencap` 的 md5，不变就先怀疑注入参数。
- 已修复：`swipe) D=$(cur_disp "$7"); input -d $D swipe $2 $3 $4 $5 ${6:-300}`。
