## 知乎在虚拟屏上的坑（已实测）

- `vdisplay launch com.zhihu.android` 后知乎会**自己跳到主屏**（`where` 变 display=0，虚拟屏抓帧全黑 6358 字节）。
- 解决办法：`cmd activity display move-stack <taskId> 197`（用 `where` 先确认任务 id/display）搬回虚拟屏，之后正常渲染（截图 ~220KB）。
- 注意 `swipe` 的脚本参数 bug：签名是 `swipe x1 y1 x2 y2 [ms] [pkg]`，但脚本取 `$6` 当包名（实为 ms）、`$7` 当 duration，所以**swipe 不要带包名**，纯 `swipe 360 1000 360 340 350` 才对——否则 input 报 "Invalid arguments for command: swipe"。
- 知乎热榜每次滑动约 750px ≈ 3 条；小步 400-500px 抓帧最稳妥，一次大滑会漏条目。

## 虚拟屏：用户侧"切过去"的入口全部实测无效

- 用户亲自测试：点击桌面上的设置图标，**不能**把虚拟屏上的任务拉到主屏。任务仍在虚拟屏（`where` = 191），主屏前台不变 —— 系统把 launcher intent 重新投递给了虚拟屏上的那个已有任务。
- 之前观察到"点图标能切回主屏"是误判：那一次是哔哩哔哩直播间页面自己把任务移到了主屏（视频/直播页会请求前台），与点图标无关。
- 结论：**唯一可靠入口是 `vdisplay takeover <pkg>`**（`cmd activity display move-stack <taskId> 0`）。最近任务、桌面图标、分屏都没有入口。
- 推论：如果某个 App 用户可能想随时接手，就不要放虚拟屏；虚拟屏只适合无人值守的批量操作。

## 虚拟屏：任务可整块迁移（纠正之前的错误结论）

- `cmd activity display move-stack <rootTaskId> 0` **在 Android 17 上有效**：把跑在虚拟屏上的任务连同 Activity 状态整块搬到主屏，前台继续，不重启、不丢状态。实测任务 #3052 从 display 186 搬到 0 后全屏显示。（之前记的"跨屏搬任务已不支持"是错的，那次是把 taskId 当 stackId 用错了。）
- 虚拟屏上的任务**不会**出现在主屏最近任务里；之前看到的"设置"卡片是残留在主屏的另一个任务。
- `vdisplay` 脚本已加 `takeover <pkg>`、`where <pkg>`，且 `tap/shot` 带包名时会自动解析任务当前所在显示器（自动跟随），接管后继续操作不会失灵。
- 用户想接手后台任务时：`takeover` + 随后 `stop`，不要用重新启动 App 的方式代替（会丢状态）。

## 虚拟屏后台执行能力（已落地）

在 Redmi（Android 17）上验证并固化了"非 root 隐藏虚拟屏"方案：

- 原理：`app_process` 以 shell uid 跑自建 dex → `createPackageContext("com.android.shell")` → `DisplayManager.createVirtualDisplay`（PUBLIC|OWN_CONTENT_ONLY，ImageReader 720×1280 表面）→ `am start --display <id>` 投放 → `input -d` 注入 → `screencap -d <SF id>` 抓帧。
- 关键坑：系统上下文包名不行（packageName must match the owner uid）；进程内 startActivity 不行（package=android does not belong to uid=2000）；系统拥有的 overlay 屏投放必被 SafeActivityOptions 拒绝，自建屏因 owner=uid2000 放行。
- 产物：`/data/local/tmp/vd.jar` + `/data/local/tmp/vdisplay` 控制脚本（start/stop/status/launch/tap/swipe/key/text/shot）；技能 `/var/minis/skills/virtual-display/`；已写入 GLOBAL.md。
- 已实测：启动设置 → 点 WLAN 进入二次页 → 抓帧确认，全程主屏前台未变。
- 限制：锁屏即失效；同一用户空间不是沙箱；视频/游戏黑屏。
- 顺带结论：`--windowingMode 5` 在 MIUI 上无效；overlay_display_devices 是镜像屏、owner 是 system，不可用。
